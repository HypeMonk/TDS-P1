# TDS GCP AI Agent Assignment — Q4 Complete Guide

This guide is the direct continuation of the Q3 guide. It covers **Q4 (Dataset Upload & Verification)** using an AI coding agent autonomously. 

We highly recommend starting a **New Task** (a brand new chat session) in Cline for this to keep your JSON logs clean and separate for the autograder. However, because this prompt is designed to be "idempotent" (it double-checks everything from Q3), it will work perfectly whether you start a new chat or continue in the same one!

---

## 1. Preparation

Before running the agent for Q4, you must manually download your personalized dataset file from the assignment portal.

1. Go to the assignment portal.
2. Under the Q4 section, click to download the `eval.jsonl` file.
3. Save it somewhere easy to access on your computer (e.g., `C:\Users\YourName\Downloads\eval.jsonl` on Windows, or `~/Downloads/eval.jsonl` on Mac).
4. Get your specific **Bucket Name** and **Project ID** ready.

### 1.1 Starting a "New Task" in Cline
To ensure your JSON log doesn't get bloated with your Q3 history, you **must** start a brand new chat.
1. Open the Cline panel in VS Code.
2. Look at the top right of the Cline window and click the **"+" (New Task)** icon.
3. This clears the chat interface and guarantees that Cline will create a brand new timestamped folder for your Q4 JSON logs!

## 2. The General Prompt for Q4

> [!NOTE]
> **Make this prompt as unique as you can.** Just like in Q3, your marks depend on the specific actions logged here. 

Replace the values in the **Details** block with your own Project ID, your assigned Bucket Name, and the exact local file path where you saved `eval.jsonl`. 

Paste this entire block as **one single message** into a fresh Cline session:

```
You are a cloud engineer agent working in a terminal. The Google Cloud CLI (gcloud) is already installed and authenticated on this machine — do not attempt to install it or run gcloud auth login unless `gcloud auth list` shows no active account.

First, detect which shell/terminal you are running in (e.g. PowerShell, cmd, bash, zsh) and use the correct command syntax for that shell throughout this task. Do not assume a shell — check first and adapt.

Complete this entire task autonomously without asking me questions — make reasonable decisions yourself and keep going until done. After each major step, print a clear status line (e.g. "STEP X DONE: ...") before moving to the next step. If a command fails, print the exact error and try one reasonable fix before moving on — don't silently skip a failed step.

Details:
- Project ID: YOUR_PROJECT_ID
- Bucket name: YOUR_BUCKET_NAME
- Location: asia-south1
- Local file to upload: C:\YOUR\EXACT\PATH\TO\eval.jsonl

Steps:
1. Verify gcloud is available and check auth status with `gcloud auth list`. Confirm the active project is YOUR_PROJECT_ID (set it if not already).
2. Compute the SHA-256 hash of the local file BEFORE upload, using the correct command for this shell (e.g. `Get-FileHash` in PowerShell, `sha256sum` in bash). Print this hash clearly labeled as "LOCAL HASH BEFORE UPLOAD".
3. Ensure the Cloud Storage API is enabled: `gcloud services enable storage.googleapis.com`.
4. Create the bucket: `gcloud storage buckets create gs://YOUR_BUCKET_NAME --location=asia-south1`. If it already exists, skip this step and note that.
5. Upload the file unchanged, preserving the exact filename `eval.jsonl`:
   `gcloud storage cp "C:\YOUR\EXACT\PATH\TO\eval.jsonl" gs://YOUR_BUCKET_NAME/eval.jsonl`
6. Make the bucket publicly readable and listable by granting `roles/storage.objectViewer` and `roles/storage.legacyBucketReader` to `allUsers`.
7. Download the uploaded object back to a temp location and compute its SHA-256 hash, or use `gcloud storage objects describe` to check the object's stored hash/metadata (via `gcloud storage objects describe gs://YOUR_BUCKET_NAME/eval.jsonl --format="value(md5Hash,etag)"` or similar). Print this clearly labeled as "UPLOADED FILE VERIFICATION".
8. Confirm by running `gcloud storage buckets describe gs://YOUR_BUCKET_NAME` and `gcloud storage ls gs://YOUR_BUCKET_NAME`.
9. Print a final summary: project confirmed, API enabled, bucket created/existing, file uploaded, LOCAL HASH BEFORE UPLOAD, UPLOADED FILE VERIFICATION, public access granted, and full describe/list output. Explicitly state whether the local hash and the uploaded file appear to match.
```

## 3. What "Good" Looks Like As It Runs

Watch for:
- **Step 2:** The agent must accurately calculate the SHA-256 hash of your local file *before* it touches Google Cloud. 
- **Step 4 (Idempotency):** Since you likely already created the bucket in Q3, the agent should try to create it, see the "Bucket already exists" error, handle it gracefully as instructed, and keep moving.
- **Step 7:** The verification step is critical. It proves the file was uploaded without corruption.

## 4. Extracting the Log for Submission

Just like in Q3, you need the raw `api_conversation_history.json` file.

> [!CAUTION]
> **Don't Mix Up Your Q3 and Q4 Logs!**
> Because every single task in Cline names its log file exactly `api_conversation_history.json`, it is incredibly easy to get them mixed up and submit your Q3 log for Q4 (which will result in a zero). 
> **Always verify the contents:** Before you paste it into the portal, open the file and read the end of it to ensure it talks about "eval.jsonl" and "uploading".

1. Navigate to the Cline tasks folder on your computer:
   - **Windows:** `%APPDATA%\Code\User\globalStorage\saoudrizwan.claude-dev\tasks\`
   - **macOS:** `~/Library/Application Support/Code/User/globalStorage/saoudrizwan.claude-dev/tasks/`
   - **Linux:** `~/.config/Code/User/globalStorage/saoudrizwan.claude-dev/tasks/`
2. Look for the folder with the most recent timestamp (this is your new Q4 chat session).
3. Open `api_conversation_history.json`.
4. Verify the end of the file shows the "final summary" with the hashes matching.
5. Copy the entire file's contents and paste it into the assignment's Q4 submission field!

## 5. Second Method: Custom Python Script

If you prefer using the Python script method (as covered in Q3), the process is identical. The only thing you need to change is the `messages` array in your `agent.py` script.

### 5.1 The Full Script (`q4_agent.py`)
Save the following code as a new file (e.g., `q4_agent.py`). It is fully self-contained and uses the exact prompt you need for Q4.

```python
import json
import subprocess
from openai import OpenAI

# 1. Setup client using aipipe as the OpenAI-compatible proxy
client = OpenAI(
    base_url="https://aipipe.org/openai/v1",
    api_key="YOUR_AIPIPE_TOKEN"  # from aipipe.org/login
)

# 2. System + task prompt — this becomes your JSONL log
messages = [
    {"role": "system", "content": "You are a cloud engineer agent. You can run terminal commands using the 'run_command' tool. Detect your shell type before running OS-specific commands, and adapt syntax accordingly."},
    {"role": "user", "content": f"""
You are a cloud engineer agent working in a terminal. The Google Cloud CLI (gcloud) is already installed and authenticated on this machine — do not attempt to install it or run gcloud auth login unless `gcloud auth list` shows no active account.

First, detect which shell/terminal you are running in (e.g. PowerShell, cmd, bash, zsh) and use the correct command syntax for that shell throughout this task. Do not assume a shell — check first and adapt.

Complete this entire task autonomously without asking me questions — make reasonable decisions yourself and keep going until done. After each major step, print a clear status line (e.g. "STEP X DONE: ...") before moving to the next step. If a command fails, print the exact error and try one reasonable fix before moving on — don't silently skip a failed step.

Details:
- Project ID: YOUR_PROJECT_ID
- Bucket name: YOUR_BUCKET_NAME
- Location: asia-south1
- Local file to upload: C:\\YOUR\\EXACT\\PATH\\TO\\eval.jsonl

Steps:
1. Verify gcloud is available and check auth status with `gcloud auth list`. Confirm the active project is YOUR_PROJECT_ID (set it if not already).
2. Compute the SHA-256 hash of the local file BEFORE upload, using the correct command for this shell. Print this hash clearly labeled as "LOCAL HASH BEFORE UPLOAD".
3. Ensure the Cloud Storage API is enabled: `gcloud services enable storage.googleapis.com`.
4. Create the bucket: `gcloud storage buckets create gs://YOUR_BUCKET_NAME --location=asia-south1`. If it already exists, skip this step and note that.
5. Upload the file unchanged, preserving the exact filename `eval.jsonl`: `gcloud storage cp "C:\\YOUR\\EXACT\\PATH\\TO\\eval.jsonl" gs://YOUR_BUCKET_NAME/eval.jsonl`
6. Make the bucket publicly readable and listable by granting `roles/storage.objectViewer` and `roles/storage.legacyBucketReader` to `allUsers`.
7. Download the uploaded object back to a temp location and compute its SHA-256 hash, or use `gcloud storage objects describe` to check the object's stored hash/metadata. Print this clearly labeled as "UPLOADED FILE VERIFICATION".
8. Confirm by running `gcloud storage buckets describe` and `gcloud storage ls`.
9. Print a final summary: project confirmed, API enabled, bucket created/existing, file uploaded, LOCAL HASH BEFORE UPLOAD, UPLOADED FILE VERIFICATION, public access granted, and full describe/list output. Explicitly state whether the local hash and the uploaded file appear to match.
"""}
]

# 3. Tool definition
tools = [{
    "type": "function",
    "function": {
        "name": "run_command",
        "description": "Run a terminal command on the user's computer",
        "parameters": {
            "type": "object",
            "properties": {
                "command": {"type": "string", "description": "The shell command to run"}
            },
            "required": ["command"]
        }
    }
}]

# 4. Agent loop
print("Starting Q4 agent...")
MAX_ITERATIONS = 25
iterations = 0

while iterations < MAX_ITERATIONS:
    iterations += 1
    response = client.chat.completions.create(
        model="gpt-5-nano",
        messages=messages,
        tools=tools
    )

    response_message = response.choices[0].message
    messages.append(response_message.model_dump(exclude_unset=True))

    if response_message.tool_calls:
        for tool_call in response_message.tool_calls:
            if tool_call.function.name == "run_command":
                args = json.loads(tool_call.function.arguments)
                command = args["command"]

                print(f"\\n[Agent wants to run]: {command}")

                try:
                    result = subprocess.run(
                        command, shell=True, capture_output=True, text=True, timeout=300
                    )
                    output = result.stdout if result.returncode == 0 else result.stderr
                except subprocess.TimeoutExpired:
                    output = "Command timed out after 300 seconds."
                except Exception as e:
                    output = str(e)

                print(f"[Command Output]:\\n{output}")

                messages.append({
                    "role": "tool",
                    "tool_call_id": tool_call.id,
                    "name": tool_call.function.name,
                    "content": output
                })
    else:
        print(f"\\n[Agent Final Answer]: {response_message.content}")
        break
else:
    print("\\nReached max iterations without the agent finishing — check the log for a stuck loop.")

# 5. Save the log
with open("q4_agent_log.jsonl", "w") as f:
    for msg in messages:
        f.write(json.dumps(msg) + "\\n")

print("\\nSaved conversation log to q4_agent_log.jsonl")
```

### 5.2 Running the Script
1. Change the bucket name, project ID, and file path in the prompt above.
2. Run `python agent.py` in your terminal.
3. Because you are running the script again, it will automatically overwrite your previous `agent_log.jsonl` with this new Q4 session (if you want to save the Q3 log, simply rename it to `q3_agent_log.jsonl` before running the script!).
4. Open the new `agent_log.jsonl` and paste its contents into the Q4 submission portal.
