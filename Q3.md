# TDS GCP AI Agent Assignment — Complete Guide

This guide covers Q3 (Bucket Setup) and Q4 (Dataset Upload) using an AI coding agent, autonomously, in a single prompt per task. It assumes you've already completed **Phase 0: GCP Free Trial Activation** from the earlier setup guide.

---

## 1. Creating a Project in Google Cloud

Every GCP resource lives inside a "Project." You need one before creating any bucket.

1. Go to [console.cloud.google.com](https://console.cloud.google.com).
2. Click the **Project Dropdown** next to the "Google Cloud" logo (top-left).
3. Click **New Project** (top-right of the modal).
4. Name it something simple, e.g. `tds-project` — GCP will auto-generate a Project ID like `tds-project-xxxxx`. **Note this exact Project ID down** — you'll need it for every command going forward.
5. Click **Create**, wait a few seconds, then select it from the top dropdown.

You can verify your project ID anytime by running:
```
gcloud config get-value project
```
(once gcloud is installed — see next section).

## 2. Installing Google Cloud SDK (gcloud CLI)

You need `gcloud` installed and on your system PATH before letting an AI agent touch it. Installing the SDK is a one-time manual setup — not something worth delegating to an agent, since it's mechanical rather than agentic.

### Windows (PowerShell)

```powershell
(New-Object Net.WebClient).DownloadFile("https://dl.google.com/dl/cloudsdk/channels/rapid/GoogleCloudSDKInstaller.exe", "$env:Temp\GoogleCloudSDKInstaller.exe")
& $env:Temp\GoogleCloudSDKInstaller.exe
```

- This launches a GUI installer wizard — click through it (Next → Next → Finish).
- Keep the default **"Add gcloud to PATH"** option checked.
- The installer may auto-open a new terminal and offer to run `gcloud init` — you can let it or cancel and do this later via your agent.
- **Close and reopen your terminal/VS Code** after install — PATH changes don't apply to already-open sessions.

### macOS

```bash
curl https://sdk.cloud.google.com | bash
exec -l $SHELL
```
This downloads and runs Google's official install script, which handles PATH setup and asks a couple of yes/no questions.

Alternative via Homebrew:
```bash
brew install --cask google-cloud-sdk
```

### Linux / WSL

```bash
curl https://sdk.cloud.google.com | bash
exec -l $SHELL
```
Same script works on WSL and native Linux.

### Verify install (any OS, fresh terminal)

```
gcloud --version
```

If this prints a version number, you're ready to move to the agent step.

## 3. Recommended Method: Cline

Two methods are covered in this guide — **Cline** (VS Code extension, easiest, no coding) and a **custom Python script** (more control, more setup). Cline is recommended as the default for most students because it requires zero agent-loop code — you install an extension, configure it once, and it handles the tool-call loop, terminal execution, and retries internally.

Use the custom script instead if you want full control over exactly what gets logged, or if you're comfortable with Python and want a lighter-weight setup without VS Code.

---

## 4. Installing and Setting Up Cline

### 4.1 Install
1. Open VS Code.
2. Go to Extensions (Ctrl+Shift+X), search **"Cline"**, install it.
3. Open the folder you want to work in (needs terminal access).

### 4.2 Get your aipipe token
1. Go to `aipipe.org/login`, sign in with your student email.
2. Copy the token shown — this is your API key for the next step.

### 4.3 Configure Cline's API provider
1. Open Cline's settings (gear icon in the Cline panel).
2. **API Provider:** choose "OpenAI Compatible."
3. **Base URL:** `https://aipipe.org/openai/v1`
4. **API Key:** paste your aipipe token.
5. **Model ID:** `gpt-5-nano` (confirmed supported by aipipe) — you can try other OpenAI-format models depending on your budget/quota.

   *Alternative:* to use other model families (e.g. Claude via OpenRouter), set Base URL to `https://aipipe.org/openrouter/v1` instead, and prefix the model ID with its provider, e.g. `anthropic/claude-...`.

### 4.4 Enable autonomy (auto-approve)
This is the critical step that makes "single prompt, autonomous" possible — without it, Cline pauses and asks you to click "Approve" before every single command.

In Cline's Auto-approve panel, enable:
- **Read project files**
- **Edit project files**
- **Execute safe commands**
- **Execute all commands**
- **Use the browser** (optional — see note below)
- **Use MCP servers** (not needed for this task, harmless either way)

**Note on "Use the browser":** if disabled, `gcloud auth login`'s browser-based OAuth flow will need you to manually copy the printed URL and open it yourself — Cline won't click through it. This is fine and expected; you'll just complete that one login step by hand.

## 5. The General Prompt and Handling Auth

> [!NOTE]
> **Make this part or prompt as unique as you can. MARKS will depend on this.**

### 5.1 The prompt 


Replace the two values in the **Details** block with your own project ID and bucket name from your downloaded task details, then paste the entire thing as **one single message** into Cline.

```
You are a cloud engineer agent working in a terminal. The Google Cloud CLI (gcloud) is already installed on this machine — do not attempt to install it.

First, detect which shell/terminal you are running in (e.g. PowerShell, cmd, bash, zsh) and use the correct command syntax for that shell throughout this task (e.g. use `;` not `&&` in PowerShell, correct path separators, correct quoting). Do not assume a shell — check first (e.g. via $PSVersionTable in PowerShell, or echo $SHELL in bash) and adapt.

Complete this entire task autonomously without asking me questions — make reasonable decisions yourself and keep going until done. After each major step, print a clear status line (e.g. "STEP X DONE: ...") before moving to the next step. If a command fails, print the exact error and try one reasonable fix before moving on — don't silently skip a failed step.

Details (use these exact values everywhere a project ID or bucket name is needed below):
- Project ID: YOUR_PROJECT_ID
- Bucket name: YOUR_BUCKET_NAME
- Location: asia-south1

Steps:
1. Verify gcloud is available: `gcloud --version`.
2. Check current auth status with `gcloud auth list`. If not authenticated, run `gcloud auth login`. This will print a URL for browser-based login — output the URL clearly and pause; I will complete the login manually in my browser. Only proceed once you detect a successful login (re-check with `gcloud auth list`).
3. Set the active project using the Project ID above. Confirm with `gcloud config get-value project`.
4. Enable the Cloud Storage API: `gcloud services enable storage.googleapis.com`. Confirm it's enabled.
5. Create the bucket using the bucket name and location above: `gcloud storage buckets create gs://BUCKET_NAME --location=LOCATION`.
6. Make the bucket publicly readable and listable by granting `roles/storage.objectViewer` and `roles/storage.legacyBucketReader` to `allUsers`.
7. Confirm everything by running `gcloud storage buckets describe` and `gcloud storage buckets list` on the bucket.
8. Print a final summary confirming: authentication status, project set, API enabled, bucket created, public access granted, and full describe/list output.
```

### 5.2 Handling the auth pause

When the agent reaches step 2:
- If you're already logged in (from earlier testing), it should detect this via `gcloud auth list` and skip straight past — this is expected and fine.
- If not logged in, it will run `gcloud auth login` and print a URL. **Copy that URL, paste it into your browser, sign in with the Google account tied to your GCP project, and approve.** Once done, switch back to Cline — the terminal unblocks and the agent's loop continues automatically. You don't need to send another message; this is still one session, one prompt.

### 5.3 What "good" looks like as it runs

Watch for:
- Step 2 actually pausing/waiting rather than rushing past without real authentication.
- Step 5 succeeding without a permissions or naming error.
- Step 6 running both IAM binding commands (object read access *and* bucket listing access are both needed for "publicly readable and listable").
- Step 8 printing a clean summary with real output, not placeholder text.

If a command fails and the agent doesn't clearly say so, don't trust a fast "success" — scroll up in the Cline panel and check the actual command outputs.

## 6. Where to Find the JSON Log and What to Submit

Cline saves every task's full conversation locally — no manual export needed.

### File location

**Windows:**
```
C:\Users\<YourUsername>\AppData\Roaming\Code\User\globalStorage\saoudrizwan.claude-dev\tasks\
```
(or paste `%APPDATA%\Code\User\globalStorage\saoudrizwan.claude-dev\tasks\` into File Explorer's address bar)

**macOS:**
```
~/Library/Application Support/Code/User/globalStorage/saoudrizwan.claude-dev/tasks/
```

**Linux:**
```
~/.config/Code/User/globalStorage/saoudrizwan.claude-dev/tasks/
```

### Which file to use

Inside the `tasks` folder, each task has its own subfolder (named by timestamp/ID). Open the most recent one — it contains:

- **`api_conversation_history.json`** — the complete raw exchange: your prompt, every command the model decided to run, and every actual terminal output. **This is the one to submit** — it's the most faithful record of what the agent actually did.
- `ui_messages.json` — a UI-formatted version of the same data; readable but less complete for grading purposes.

### Before submitting

Open `api_conversation_history.json` and confirm you can see, in order:
- The auth check/login sequence
- Project set confirmation
- Storage API enable command + confirmation
- Bucket create command
- Both IAM policy binding commands
- Describe and list output

If all of that is visible, copy the entire file's contents and paste it into the assignment's "agent_log_jsonl_file content" field. Exact file extension/formatting doesn't matter — only that the content shows the real agent-driven command sequence.

## 7. Second Method: Custom Python Script

For students who prefer full control over the agent loop and exactly what gets logged, or want to avoid installing VS Code/Cline.

### 7.1 Requirements

```bash
pip install openai
```

### 7.2 The script

```python
import json
import subprocess
from openai import OpenAI

# 1. Setup client using aipipe as the OpenAI-compatible proxy
client = OpenAI(
    base_url="https://aipipe.org/openai/v1",
    api_key="YOUR_AIPIPE_TOKEN"  # from aipipe.org/login
)

# 2. System + task prompt — this becomes your JSONL log
messages = [
    {"role": "system", "content": "You are a cloud engineer agent. You can run terminal commands using the 'run_command' tool. Detect your shell type before running OS-specific commands, and adapt syntax accordingly."},
    {"role": "user", "content": (
        "gcloud is already installed. Do not install it. "
        "Check auth status with `gcloud auth list`; if not authenticated, run `gcloud auth login` "
        "and pause for me to complete browser login. Then set project to YOUR_PROJECT_ID, "
        "enable storage.googleapis.com, create bucket gs://YOUR_BUCKET_NAME in asia-south1, "
        "make it publicly readable and listable (grant allUsers both roles/storage.objectViewer "
        "and roles/storage.legacyBucketReader), then run describe and list to confirm. "
        "Print status after each step."
    )}
]

# 3. Tool definition
tools = [{
    "type": "function",
    "function": {
        "name": "run_command",
        "description": "Run a terminal command on the user's computer",
        "parameters": {
            "type": "object",
            "properties": {
                "command": {"type": "string", "description": "The shell command to run"}
            },
            "required": ["command"]
        }
    }
}]

# 4. Agent loop
print("Starting agent...")
MAX_ITERATIONS = 25
iterations = 0

while iterations < MAX_ITERATIONS:
    iterations += 1
    response = client.chat.completions.create(
        model="gpt-5-nano",
        messages=messages,
        tools=tools
    )

    response_message = response.choices[0].message
    messages.append(response_message.model_dump(exclude_unset=True))

    if response_message.tool_calls:
        for tool_call in response_message.tool_calls:
            if tool_call.function.name == "run_command":
                args = json.loads(tool_call.function.arguments)
                command = args["command"]

                print(f"\n[Agent wants to run]: {command}")

                # NOTE: gcloud auth login will require you to manually open the
                # printed URL in a browser and sign in — the script cannot do this.
                try:
                    result = subprocess.run(
                        command, shell=True, capture_output=True, text=True, timeout=300
                    )
                    output = result.stdout if result.returncode == 0 else result.stderr
                except subprocess.TimeoutExpired:
                    output = "Command timed out after 300 seconds."
                except Exception as e:
                    output = str(e)

                print(f"[Command Output]:\n{output}")

                messages.append({
                    "role": "tool",
                    "tool_call_id": tool_call.id,
                    "name": tool_call.function.name,
                    "content": output
                })
    else:
        print(f"\n[Agent Final Answer]: {response_message.content}")
        break
else:
    print("\nReached max iterations without the agent finishing — check the log for a stuck loop.")

# 5. Save the log
with open("agent_log.jsonl", "w") as f:
    for msg in messages:
        f.write(json.dumps(msg) + "\n")

print("\nSaved conversation log to agent_log.jsonl")
```

### 7.3 Key differences from Cline

| | Cline | Python Script |
|---|---|---|
| Setup effort | Install extension, click settings | Write/copy ~70 lines of code |
| Auth login pause | Handled automatically by terminal blocking | Also blocks naturally — script waits on `subprocess.run` until you complete login and the command returns |
| Log format | JSON files auto-saved by Cline | You control the exact JSONL structure yourself |
| Runaway loop protection | Cline has its own internal limits | You must set `MAX_ITERATIONS` yourself (included above) |
| Debugging if stuck | Read through VS Code UI/task history | Just re-run the script, add print statements |

### 7.4 Running it

```bash
python agent_script.py
```

Watch the terminal as it runs — when it hits `gcloud auth login`, it will print a URL as part of the command output; open that in your browser, sign in, and once you see the success page, the underlying `gcloud auth login` process itself typically returns automatically and the script continues.

### 7.5 Submitting the log

`agent_log.jsonl` is created in the same folder you ran the script from — open it and paste its full contents into the assignment submission field, same as the Cline method.

## Quick Reference: Common Pitfalls

- **Wrong shell syntax** (e.g. `&&` in PowerShell) — always tell the agent to detect its shell first.
- **Stale/hardcoded SDK download URLs** — install gcloud yourself manually rather than letting the agent guess a version.
- **PATH not updated** — always open a fresh terminal after installing gcloud.
- **Only one IAM role granted** — "publicly readable and listable" needs both `objectViewer` (read) and `legacyBucketReader` (list) granted to `allUsers`.
- **Multiple prompts instead of one** — the assignment requires a single session, single prompt; pausing for a browser login mid-task is fine and doesn't count as a second prompt.
- **Submitting the wrong file** — for Cline, use `api_conversation_history.json`, not `ui_messages.json`.
